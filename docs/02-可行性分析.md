# 02 可行性分析 — Android 深度定制超级 AI 助手

> 阶段：市场分析 / 原型选型 | 日期：2026-08-18
> 方法：逐能力模块评估「技术可行 / 平台可行 / 资源可行 / 风险与缓解」，全部以既有实证（Kestrel 真机、Hermes-Termux、sherpa-onnx Android、MiraAgent 研究）为锚点。

---

## 0. 总体结论（先行）

| 维度 | 结论 |
|------|------|
| 技术可行性 | ✅ **高**。四大来源项目分别实证了 4 条关键链路：Termux 跑完整 Agent（Hermes）、端侧语音栈（Kestrel+sherpa-onnx）、无障碍操控（Kestrel 真机成单）、系统级权威设计（MiraAgent） |
| 平台可行性 | ✅ 免 root 可达（a11y+MediaProjection/截图+前台服务）；ROM 层为增强项非依赖项 |
| 资源可行性 | ⚠️ 可行但需分级加载：端侧模型包体大（ASR 227MB + TTS ~100MB+），内存/功耗需管理 |
| 合规可行性 | ⚠️ 可行：支付红线 + HITL + 脱敏 + 录音/屏幕权限显式授权；声纹数据需个人信息合规设计 |
| **综合判定** | **立项可行，建议 P0 原型验证 8 周**：Termux 大脑 + Java 躯体的 IPC 链路、端侧语音全家桶、基础操控闭环 |

## 1. Agent 核心运行（Termux + Pi agent-core）

| 项目 | 评估 |
|------|------|
| 前置事实 | Hermes 已官方支持 Termux（自动检测 Termux，`pkg install git python nodejs ripgrep ffmpeg`，为 Android wheel 导出 `ANDROID_API_LEVEL`）→ **Termux 上跑 Node/Python Agent 已被证实可行** |
| Pi 依赖 | `@earendil-works/pi-agent-core` 为纯 TypeScript，无原生依赖（SQLite 后端是独立可选包，可换内存后端）；`@earendil-works/pi-ai` 纯 HTTP 流式调用 → **Termux Node 22 可直接跑** |
| 资源 | Node 常驻内存 ~100–200MB（含依赖加载），旗舰机可行；低端机需 --max-old-space-size 调优 |
| 通信 | Termux 进程 ↔ Android Java 服务：localhost HTTP/WebSocket（Termux 默认有网络能力）+ Intent 唤醒（termux-api / RUN_COMMAND）；**局域网回环不要求额外权限** |
| 风险 | Termux 进程可能被系统杀（后台限制）→ 由 Java 前台服务持有 + 检测到进程死亡自动重启（Termux:Boot / RUN_COMMAND）；深度定制阶段可降级为"同进程内嵌 Node"或"Java 重写核心" |
| **判定** | ✅ **可行**。仅复用 pi 核心（loop/工具/事件/steering），外围全由 Java/C++ 承担，符合用户"只复用核心部分"约束 |

## 2. 硬件接入模块（听筒/扬声器/耳机/Mic/传感器/振动）

| 能力 | API | 可行性 | 备注 |
|------|-----|--------|------|
| 听筒/扬声器路由 | `AudioManager.setSpeakerphoneOn` / `setCommunicationDevice`（API31+ CommunicationDevice） | ✅ 稳定 SDK | 语音通话模式（听筒）/免提/蓝牙/TypeC 耳机切换；`AudioDeviceCallback` 监听插拔 |
| 耳机外设 | `registerAudioDeviceCallback` + `getDevices(GET_DEVICES_OUTPUTS)` | ✅ 稳定 SDK | 识别耳机插入/拔出，TTS 自动改路由到耳机 |
| 播放 | AudioTrack（PCM 流式）/ ExoPlayer（音频文件） | ✅ | 流式 TTS 低延迟播放；`setPreferredDevice` 精确选设备 |
| 录音 Mic | AudioRecord 16k/48k 单声道 | ✅ 需 `RECORD_AUDIO` 运行时授权 | Kestrel 已实证（AudioRecord→SenseVoice）；**无 GMS 华为机可用** |
| 传感器 | `SensorManager`（加速度/陀螺仪/磁力/光线/接近/气压/步数） | ✅ 稳定 SDK | 环境感知：静置/拿起/行走/翻转；无需权限 |
| 振动 | `Vibrator` + `VibrationEffect.createWaveform` | ✅ 稳定 SDK | 自定义振动模式（提醒/来电式/节拍），API26+ 波形 |
| 蓝牙 | `BLUETOOTH_CONNECT` 权限 + Media2/AudioDeviceCallback | ✅ | 耳机路由、音频输出 |
| 硬件故障模拟 | 深度定制 ROM 可 mock（MiraAgent 高保真模拟 Provider 思想） | ✅ | 统一 Provider 端口，mock 与 real 同契约 |

**判定**：✅ **完全可行**。全部为稳定公开 SDK，Kestrel 真机已覆盖 Mic 链路；音频路由是 Java 侧原生职责（Termux 不碰硬件，职责分离清晰）。

## 3. 语音业务（TTS / ASR / 声纹 / 音色 / 语气 / 语调）

| 能力 | 候选引擎 | 可行性 | 实证 |
|------|---------|--------|------|
| ASR | sherpa-onnx + SenseVoice int8（离线、中英混说、227MB） | ✅ 已在 Android 真机跑通 | Kestrel infra-speech 实证（华为 Mate40Pro 无 GMS） |
| ASR 流式/VAD | sherpa-onnx streaming ASR + Silero VAD | ✅ 官方 Android 支持 | clowder VAD 打断模式可移植 |
| TTS | sherpa-onnx：VITS（zh）/ Matcha / **Kokoro（中文高质量）** / ZipVoice / Pocket（**声音克隆**） | ✅ 官方 Android AAR | 端侧合成免网络；Kokoro 中文为 2025+ 成熟模型 |
| 音色/语气/语调 | **参考音频克隆 + instruct 指令**（Qwen3-TTS 思路，Clowder VoiceConfig 契约：`voice/langCode/speed/refAudio/refText/instruct/temperature`） | ✅ | Clowder F103 已实证"每角色独立声线"；端侧可用 sherpa 克隆模型近似 |
| 声纹（说话人识别） | sherpa-onnx speaker recognition（Wespeaker/ECAPA-TDNN）+ 说话人嵌入 | ✅ 官方支持 | 与 ASR/TTS 同一 C++ 栈（sherpa-onnx），12 类语音功能一体 |
| 云端增强 | 火山云 ASR/TTS（MiraAgent 选型）、Qwen3-TTS（Clowder 最终选型） | ✅ | 端侧为主、云端可选 |
| 离线 vs 在线 | 端侧优先，云端兜底 | ✅ | 分级：离线单机 / 在线增强（情绪表达、多音色） |

**判定**：✅ **完全可行**。sherpa-onnx 一栈覆盖 ASR+TTS+VAD+声纹+关键词（C++ 核心 + Java/Kotlin API + Android AAR），Clowder 音色配置模型可直接照搬为 JSON 契约。

## 4. 操控模块（按键 / 触屏 / 手势）

| 能力 | 注入方式 | 可行性 | 实证/风险 |
|------|---------|--------|----------|
| 触摸点击/滑动 | AccessibilityService `dispatchGesture` | ✅ 免 root | Kestrel 真机实证：110ms+2px 微位移治 H5 不识别；Android 12 不可信触摸拦截需 HUD alpha<0.8 穿透 |
| 语义点击（TV/无触屏） | a11y `ACTION_CLICK`/`ACTION_SCROLL_*`/`ACTION_LONG_CLICK` | ✅ 免 root | Kestrel v2.0 TV 实证，D-pad 可达 |
| 文本输入 | a11y `ACTION_SET_TEXT`（focus 优先） | ✅ | Kestrel 实证；密码框走 HITL |
| 全局按键（Back/Home/菜单/音量） | ① `performGlobalAction`（a11y，Back/Home 免费）② 注入 KEYCODE 需 Shizuku/adb（`input keyevent`） | ⚠️ 部分 | 免 root 只能 Back/Home/Recents；**深度按键注入（音量键、电源、组合键）依赖 Shizuku 或 ROM 层** |
| 手势（双指/复杂） | dispatchGesture 支持多指针 Path | ✅ | Kestrel Action DSL 已含 Tap/LongPress/Swipe，扩展 Pinch 等 |
| 坐标换算 | Norm 0..999 归一化 + 位图像素中心（Kestrel 经验） | ✅ | 规避 OCR 坐标偏移坑（displayMetrics vs 截图空间） |
| ROM 层注入（深度定制） | InputManager.injectInputEvent（MiraAgent 执行平面） | ✅ 需 AOSP 构建 | 深度定制档位能力，普通 App 不可用 |

**判定**：✅ **基本可行**（免 root 覆盖 95% 场景）；按键注入留 Shizuku/ROM 双档位。Kestrel 已把"注入不可靠"系统性转化为确定性机制（located 如实反馈、像素校验、防幻觉闸门），可整体移植。

## 5. 屏幕识别（a11y / OCR / 视觉）

| 能力 | 方案 | 可行性 | 实证/风险 |
|------|------|--------|----------|
| a11y 树感知 | AccessibilityService 遍历（交互节点提取） | ✅ | Kestrel 实证；H5/Canvas 不在 a11y 树（TOP-1 坑） |
| 截图 | a11y `takeScreenshot`（免 MediaProjection）或 MediaProjection（API30+ 需授权） | ✅ | Kestrel 实证 JPEG q78；`OverlayGate` 防自家 HUD 入镜 |
| OCR（端侧） | PaddleOCR-ONNX（需打包）/ ML Kit 中文（Kestrel 已用） | ✅ | 用于文本化 set-of-marks + 坐标定位 |
| 视觉理解（端侧） | 本地 VLM（Qwen2.5-VL-3B/7B int4，llama.cpp/MLC 可跑但慢） | ⚠️ 慢 | 低端机 3–10s/帧，建议仅离线兜底 |
| 视觉理解（云端） | 可配置视觉模型（VISION_MODEL；实证 GLM-4.6V / GPT-4o，截图→坐标 grounding） | ✅ | Kestrel 主路实证（视觉徽章 SoM 画编号上截图） |
| 感知路由 | 可信度路由（a11y 0.9 / 视觉 0.6 / 云端兜底） | ✅ | Kestrel RouteDecider + BlankGuard 白屏守门 |
| 页面签名 | UiSignature SHA-256（a11y）/ aHash 8×8（视觉） | ✅ | 感知/执行/技能三方同源，防 NoProgress 误判 |

**判定**：✅ **完全可行**。全链路 Kestrel 真机验证；新增 PaddleOCR 端侧 OCR 替代 ML Kit（无 GMS 更稳）为可选增强。

## 6. 复杂业务路径规划（技能缓存 + 云规划 + 本地规划）

| 能力 | 方案 | 可行性 | 实证 |
|------|------|--------|------|
| 技能缓存（路径 A） | SKILL.md 数据型技能 + 回放 + Curator 治理 | ✅ | Kestrel 实证（零模型回放、STALE/ARCHIVED 状态机） |
| 云端规划（路径 B） | ReAct + Function Calling（可配置主模型，实证 GLM-4.6V） | ✅ | Kestrel 实证真机成单→支付页硬停手 |
| 本地规划兜底 | llama.cpp + Qwen3.5-2B int4（Termux 可跑！） | ⚠️ 慢但可用 | Kestrel on-device-llm-fallback 已通电（文本决策） |
| 离线技能选择 | 2-gram TF-IDF 余弦 ≥0.30 确定性回放 | ✅ | Kestrel OfflineFirst 实证 |
| 复杂业务编排 | 多步依赖、支付红线、订单跟踪（WorkManager 链式轮询） | ✅ | Kestrel 实证 |
| 系统级规划权威 | MiraAgent GRAPH/TASK/预算租约/fencing（ROM 档位） | 📋 设计就绪 | 需求/规格文档已批准，生产未实施 |
| 多 Agent 分工 | Clowder A2A（@mention / targetCats / multi_mention 状态机） | ✅ 设计可移植 | 第一阶段单 Agent 多角色，第二阶段多 Agent |

**判定**：✅ **可行**。Kestrel 双路径已闭环真机成单；MiraAgent 提供系统级权威（幂等/fencing/预算）作为 ROM 档位的架构约束，两者不冲突（前者是"会干活"，后者是"干得对、干得可恢复"）。

## 7. 平台与资源可行性

### 7.1 权限清单（免 root 形态）

| 权限 | 用途 | 授权成本 |
|------|------|---------|
| 无障碍服务 | 感知 + 触摸注入 + 截图 | 用户设置页手动开启（一次） |
| RECORD_AUDIO | Mic 语音输入 | 运行时弹窗 |
| 悬浮窗 | 悬浮球/HUD | 设置页授权（可申请） |
| 前台服务（FOREGROUND_SERVICE_MICROPHONE 等） | 常驻 + 录音 | 通知常驻 |
| POST_NOTIFICATIONS | 进度/订单/HITL 通知 | 运行时弹窗 |
| 通知使用权（NotificationListener） | 订单推送快路径（可选） | 设置页授权 |
| WRITE_SECURE_SETTINGS（adb 授予一次） | A11yRebinder 自愈 | 开发机 adb 一次，免 root |

**判定**：✅ 全部为常规可授权能力，Kestrel 已全部打通（含 A11yRebinder 自愈被系统解绑）。

### 7.2 资源预算（旗舰机 8G 内存基准）

| 组件 | 内存 | 说明 |
|------|------|------|
| Node（pi-agent-core） | ~150MB | 常驻，可降级到 100MB |
| sherpa-onnx ASR（SenseVoice int8） | ~250MB（模型 mmap） | 懒加载，按需释放 |
| sherpa-onnx TTS | ~150–300MB | 与 ASR 互斥加载（同一 .so，模型文件按需） |
| OCR（PaddleOCR 精简） | ~100MB | 懒加载 |
| 总峰值 | ~600–800MB | 可接受；低端机走"云增强模式" |
| 功耗 | 语音任务瞬发 <1W，常驻 0.2–0.5W | 前台服务 + Doze 豁免需 WorkManager 定时保活 |

**判定**：⚠️ 需分级加载架构（资产按需 mmap + LRU 卸载），Kestrel 已实践"懒加载省常驻内存"。

### 7.3 后台保活

| 威胁 | 缓解（Kestrel 实证） |
|------|---------------------|
| EMUI iAware 杀 a11y | A11yRebinder：检测"设置仍启用却被解绑"→ 自改写 `enabled_accessibility_services` 重绑 |
| 进程被杀 | 前台服务 + 用户引导免优化 + 深度定制档位可写 `settings` 白名单 |
| Termux 进程被杀 | Java 侧 watchdog：周期探测 localhost 健康接口，死亡自动重启（RUN_COMMAND） |

## 8. 合规与安全可行性

| 议题 | 风险 | 对策 | 来源 |
|------|------|------|------|
| 支付 | 自动代付 | **支付红线**：`isPaymentCommit` 只看被操作目标元素文字，绝不匹配输入载荷；HITL 确认也绝不代点；sensitiveHandoff 记成功 | Kestrel 真机实证 |
| 隐私（录音/截图/声纹） | 敏感数据外泄 | 端侧优先（语音不出端）；截图脱敏（RedactionRegions/遮黑/置空）；声纹数据本地存储+加密+明示授权 | Kestrel + MiraAgent SEC |
| 敏感操作 | 误操作 | HITL 一等公民：敏感操作必确认、验证码人工回填、风控转人工 | Kestrel |
| 未授权操控 | App 越权 | 逐 App 授权校验（Kestrel）；ROM 档位 AppOps/SELinux（MiraAgent） | 双来源 |
| 反爬/对抗 | 平台风控 | 反爬不对抗原则：诚实失败 + HITL | Kestrel |
| 个人信息（声纹/行为） | 法律风险 | 显式告知 + 可选关闭 + 本地优先；MiraAgent 渐进信任 | 双来源 |
| 自动化滥用 | 营销/刷单 | 场景白名单 + 频率限制 + 审计日志 | 自研 |

**判定**：✅ 合规路径清晰，全部红线机制已有真机实证（Kestrel 对抗审计 30+10 agent）。
