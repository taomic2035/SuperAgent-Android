## 1. Agent 内核：pi-agent-core vs 自研 vs 现成 Kotlin 引擎

| 方案 | 优点 | 缺点 | 判定 |
|------|------|------|------|
| **A. pi-agent-core（Termux，推荐）** | 生产级 Agent loop（steering/事件流/并行工具/前后钩子）；社区活跃 92.5k star；零原生依赖可跑 Termux；符合"只复用核心" | Node 进程额外 150MB；跨进程 IPC 增加复杂度；工具生态需自行接 Android 能力 | ✅ **推荐** |
| B. 移植 Kestrel orchestrator（Kotlin 重写） | 已含手机领域知识（技能/守卫/HITL） | 与 Pi 能力重复；Kestrel 编排绑定其自身端口模型，改造量大 | ❌ 作参考不照搬（领域逻辑移植到"躯体工具"层） |
| C. 全自研 Java Agent loop | 无依赖 | 重造轮子，成本 3–6 个月，质量不达 Pi | ❌ |
| D. 混合：Pi 管对话/工具，Java 管领域守卫 | 责任清晰 | 与 A 本质相同，D 是 A 的实现细节 | ✅ A 内实现 |

**决策**：**A**。pi-agent-core 的 `beforeToolCall/afterToolCall/steering/shouldStopAfterTurn` 钩子恰好承载 Android 领域守卫（支付红线、HITL 确认、技能命中）——领域规则以"工具钩子"注入，不 fork 内核。

| 方案 | 说明 | 判定 |

## 3. 语音栈（ASR / TTS / 声纹 / VAD）

### 3.1 引擎级选型：sherpa-onnx 一栈 vs 多引擎拼装

| 维度 | sherpa-onnx（推荐） | 拼装（faster-whisper+edge-tts+speechbrain） | 云引擎 |
|------|---------------------|----------------------------------------------|--------|
| 覆盖 | ASR/TTS/VAD/声纹/关键词 12 类 | 需 3–4 个引擎 | 全云 |
| Android 支持 | 官方 AAR + Java/Kotlin API | 各自移植 | 无 |
| 离线 | ✅ | ✅ | ❌ |
| 统一性 | 一个 .so 一个生命周期 | 多原生库冲突风险 | n/a |
| 选型结论 | ✅ | ❌ 复杂 | 仅作增强 |

### 3.2 具体模型选型

| 能力 | 候选 | 推荐 | 理由 |
|------|------|------|------|
| ASR | SenseVoice / Paraformer-zh / Qwen3-ASR-0.6B / Whisper | **SenseVoice int8** | Kestrel 真机实证、中英混说、227MB、整段识别 |
| ASR 流式 | Moonshine / Qwen3-ASR streaming | 备用 | 实时字幕/打断场景再引入 |
| VAD | Silero VAD（sherpa-onnx） | ✅ | 自动断点 + 打断（clowder onSpeechStart→interrupt 模式） |
| TTS 中文 | VITS-zh / Kokoro / MeloTTS | **Kokoro（中文）** | 质量高、速度合理；VITS 为保底 |
| TTS 克隆 | ZipVoice / Pocket（sherpa 官方克隆） | **ZipVoice（端侧克隆）** | 实现 Clowder ref_audio 音色克隆的端侧版 |
| TTS 云端增强 | Qwen3-TTS clone（Clowder 最终选） | 可选 | 高级音色/情绪表达走云 |
| 声纹 | Wespeaker ECAPA-TDNN（sherpa 说话人识别） | ✅ | 与 ASR 同栈；用户注册声纹 → "听到是主人" + 多角色语音命令分流 |

### 3.3 音色/语气/语调契约（照搬 Clowder VoiceConfig）

```json
{
  "voice": "kokoro_zh / zipvoice_clone",
  "langCode": "zh",
  "speed": 1.0,
  "refAudio": "assets/voices/assistant-hello.wav",
  "refText": "快醒醒，太阳要晒屁股咯……",
  "instruct": "用一个调皮狡黠的少年语气说话，带着得意和戏弄",
  "temperature": 0.3
}
```

- 每个 AI 角色一份 VoiceConfig（JSON 数据，运行时热切换）；
- TTS 缓存 hash 必须包含 refAudio+refText+instruct+temperature（Clowder 踩坑：漏 refText 声线串台）；
- 输出管线：**流式分句（句号/问号/感叹号断点）+ 播放队列（interrupt/优先级）+ 音频路由（耳机优先）**（Clowder StreamingTtsChunker + PlaybackManager 移植为 Kotlin）。

## 9. IPC 与进程拓扑（关键决策）

```
┌─ Termux 进程（大脑，Node）─────────────────────────┐
│  pi-agent-core loop │ pi-ai │ 工具注册表 │ 会话SQLite │
└───────────▲────────────────────────────────────────┘
            │ localhost HTTP (JSON-RPC) + WebSocket (流式事件)
┌───────────▼────────────────────────────────────────┐
│ Android 前台服务（躯体，Java/Kotlin）              │
│  HardwareProvider │ SpeechStack(JNI sherpa) │      │
│  GestureBackend(a11y) │ Perception │ SkillStore    │
│  HITL │ 悬浮球/通知 │ watchdog(Termux探活重启)      │
└────────────────────────────────────────────────────┘
```

- **协议**：JSON-RPC over HTTP（命令/回执）+ WebSocket（事件流：进度/语音块/流式 TTS，复用 Clowder voice_stream 事件语义）；
- **鉴权**：localhost + token（Java 侧生成，Termux 启动参数传入）；拒绝外部连接；
- **职责边界**：Termux 只做"认知/规划/对话"，**一切 Android 能力（硬件/操控/感知/语音）都是注册到 pi 的 Tool**，由 Java 侧实现后经 IPC 暴露；
- **保活**：Java watchdog 探测 `/health`，Termux 死亡 → RUN_COMMAND 重启；Termux 崩溃不影响躯体（传感器/悬浮球仍活）。

## 10. 落选方案与理由（记录在案）

| 落选 | 理由 |
|------|------|
| Termux 内跑 Python（Hermes 路线） | 与 Node/Pi 生态重复；语音/操控仍需 Java；留作工具层备用 |
| MCP 桥接 | Pi 明确不做 MCP 内建（README 拒绝列表）；Android 本地能力走自定义工具更轻 |
| edge-tts / 云 TTS 主路 | 断网不可用、延迟、隐私；仅云端增强 |
| ML Kit OCR 主路 | PaddleOCR 中文更强且无 GMS 依赖；ML Kit 留备用 |
| 全 Kotlin 重写 Agent loop | 与复用 Pi 的决策矛盾，成本高 |
| Termux 直连硬件（termux-api） | 能力不足（无 a11y 注入/屏幕识别），Java 躯体是必需 |
| AOSP ROM 作为唯一交付形态 | 周期长门槛高；以普通 App 为默认档，ROM 为增强档 |

## 11. 选型结论

1. **大脑**：pi-agent-core（Termux/Node）——唯一复用的外部 Agent 核心，其余全 Java/C++；
2. **语音**：sherpa-onnx 一栈（SenseVoice ASR + Kokoro TTS + ZipVoice 克隆 + Wespeaker 声纹 + Silero VAD），VoiceConfig 契约照搬 Clowder；
3. **躯体**：Java 原生（AudioManager/SensorManager/Vibrator/AccessibilityService），操控/感知/技能全套移植 Kestrel；
4. **权威**：MiraAgent 不变量集作为深度定制档的架构约束与验收标准；
5. **通信**：localhost HTTP+WS + watchdog 保活；
6. **演进**：免 root App（P0）→ Shizuku 增强（P1）→ AOSP 深度定制（P2，MiraAgent 路线）。
