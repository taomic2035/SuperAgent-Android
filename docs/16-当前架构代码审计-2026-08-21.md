## 1. 执行摘要

项目的主干边界是成立的：brain 负责认知与编排，body 持有设备副作用；Bearer token、协议版本、幂等键、ActionExecutor、ActionGate、敏感会话 nonce 和证据闸门均已落地。当前最值得保留的设计是：**弱模型无工具、提交边界由 body 硬拦、技能回放复用动作入口、任务成功必须有新颖屏幕证据**。

本轮同时确认 3 个高优先级缺口：

1. `control.selectOption` 的最终内部 tap 未经过坐标全节点闸门，ActionExecutor“唯一入口”仍有内层旁路。
2. 显式 vision 模式在同步真实前台包名前判敏感态，存在敏感屏截图导出窗口。
3. run 终态由工具和外层 wrapper 重复写入，造成重复归档；`closed` 的实现又与“不可续”定义冲突。

此外，截图授权回调未接入、WebView auto 路由信号丢失、暂停/继续没有恢复闭环、离线文字输入会假受理、技能提示覆盖主人记忆等问题，使 README 和架构文档对当前能力有过度陈述。

## 3. 已确认的架构强项

### 3.1 权限与副作用分权

- brain 不直接调用 Android API；设备动作通过 body RPC。
- 本地模型降级层工具集为空，弱模型不持设备控制权。
- 协议不匹配 fail-fast，不以重试掩盖版本漂移。

### 3.2 安全主链

- 提交边界词表以 `commit_boundaries.json` 为单源，brain 不镜像业务词表。
- Tap、LongPress、Swipe 起点走坐标全节点检查；敏感会话内感知失败 fail-closed。
- HITL nonce 绑定动作标签、前台包和 120 秒时窗，并一次性消费。
- 技能回放通过 `ActionExecutor`，没有直接从 `SkillStore` 调 `Controller` 的主路径。

### 3.3 完成与止损

- `task.finish` 有存在性、新颖性硬门和相关性软门。
- 连续证据驳回会升级转人工建议。
- ReActGuard 在任务间 reset，并保留感知、收尾、人工通道作为止损出口。

### 3.4 数据与契约

- `contract.json`、Kotlin Protocol、TypeScript types 有自动镜像检查。
- 记忆采用 body SQLite 权威库，write/import 有基础 PII 纵深拒绝。
- run 同时保留 brain 侧近期快照和 body 侧全量归档的设计方向合理。

## 5. 高优先级发现

### C-01：selectOption 内部点击旁路坐标闸门（✅ 2026-08-21 GPT 修复）

`ActionExecutor` 对 `Select(label)` 只校验传入 label，然后委托 `OptionSelector` 定位。`verifySelected=true` 分支在最终坐标前调用 ActionGate，但普通 `selectOption` 分支直接 `controller.tap()`。

影响：良性父节点或重叠节点的中心可能同时命中提交按钮。传入 label 不命中红线，但真实落点命中提交节点，违反“所有坐标副作用检查全部包含节点”的安全不变量。

处置：最终坐标是权威。两个分支都必须在 tap 前调用 ActionGate；参数 label 校验只能作为提前拒绝，不能替代落点校验。

修复证据：`OptionSelector` 两条选择分支共用“最终坐标闸门 → tap”路径，并以 `SelectionResult.GateBlocked(ActionGate.Violation)` 原样传递提交边界或敏感会话 nonce；`ActionExecutor` 映射为自身 typed `GateBlocked`。生产构造强制注入非空 `SensitiveSessionTracker`，选择器已收窄为 body-core 内部 API。聚焦回归 7/7 与 control/security 套件通过；完整构建证据在本批次提交前验证中统一记录。

### C-02：显式 vision 的敏感态同步顺序错误

auto 模式先 a11y、同步 `onForeground()`，再决定截图；显式 vision 模式直接使用 tracker 旧值判断是否敏感。用户手动切入银行、支付或社交 App 后，首次显式 vision 调用可能在 body 认识新前台包之前产生 screenshotRef。

处置：所有感知 mode 统一执行 a11y preflight：读取真实前台包、更新敏感会话，再路由 a11y/vision。敏感会话不生成 blob，而不是生成后再拒绝下载。

### C-05：终态所有权不唯一（✅ 2026-08-21 GLM 修复：工具弃写终态+finishRun 幂等门+RESUMABLE 策略表+resume 新生命周期；claim S2-C05）

`task.finish` 工具内部写 success；text、REPL、voice wrapper 在 Agent 返回后再次写 success/closed。`finishRun()` 本身不幂等，因此同一 run 可进入本地历史与 SQLite 多次。

同时，`closed` 注释定义为不可续，但 `peekRun()` 只排除 success。用户停止还可能先写 failed，再被外层覆盖为 closed。

处置：采用“wrapper 是终态唯一写者”：工具只 `markFinishVerified()` 并返回；wrapper 根据 finishVerified、stop、异常确定一次终态。`finishRun` 增加幂等门，resumable 使用显式策略表。

## 6. 感知与交互发现

### C-03/C-04：视觉链宣称高于实现（✅ 2026-08-21 GLM 修复：attach 闭环 + className 结构化信号；旧 label 匹配实为失效——中文页面永不触发；真机入口验证待设备）

- 主界面发起屏幕捕获授权，但回调没有调用 `ScreenshotService.attach()`。
- ScreenPerceiver 内部知道是否出现 WebView，却没有把信号交给 BodyCore；BodyCore 转而在可见 label 中查字符串 “WebView”。

因此当前可确认的是“视觉协议、blob、截图实现和 VLM brain 侧代码存在”，不能确认“用户入口可用”和“WebView 自动切视觉”。两项修复并真机标定前，L1/L2 应标为部分完成。

### C-06/C-07/C-13：用户控制状态没有形成协议闭环

- pause 命中后 `beforeToolCall` 返回 terminate；resume 只清标志，没有恢复已终止的 Agent turn。
- UI 立即打开控制面板，brain 最多约 500ms 后才消费 pause_request。
- OFFLINE 仍接受文字事件并显示“已收到”；brain 重启初始化水位时跳过这些历史事件。
- PAUSING、STOPPING 只有展示定义，没有可靠事件生产者。

目标语义应改为：暂停请求先进入 PAUSING；动作边界 settle 后把 run 持久化为 paused；resume 以断点续跑方式重新 prompt。离线输入要么明确拒绝，要么持久化为带 commandId 的待处理命令，不能假受理。

## 7. 记忆与归档发现

### C-08：记忆注入被技能提示覆盖

主人记忆块先写入 `enrichedInput`；技能命中后使用原始 `input` 重建字符串，导致记忆块消失。应使用结构化 prompt parts，固定顺序为：安全系统规则 → 主人记忆 → 技能建议 → 当前任务。

### C-09/C-11/C-14：隐私防线和备份承诺不完整

- revise 未复用 write/import 的 PII 拒绝。
- Termux 快照是明文 JSON；运行目录位于仓库根时会生成未忽略的 `.super-agent/`。
- 快照覆盖写不是原子替换，没有 schemaVersion、checksum 或 last-good 文件。

“不丢记忆”目前应表述为“已有本地定时快照与人工恢复”，不能表述为完整备份保证。最低整改包括：统一 validate、仓库忽略、0600 权限、临时文件+原子 rename、版本与校验和、恢复前校验。

## 8. IPC 与可靠性发现

BodyServer 以 `GlobalScope.launch` 执行 handler，latch 超时只停止等待，不取消协程。（✅ 2026-08-21 GLM 修复：结构化 scope+超时取消+幂等闭环+unknown_side_effect 语义+动作提交前 cancellation 检查；claim S4-C10；超时-晚到-重试链真机验证待设备）对慢技能或动作而言，brain 收到 TIMEOUT 后，body 仍可能完成副作用。幂等键防止相同 key 重复执行，但不能告诉用户第一次操作最终是否发生。

目标架构需要：结构化 CoroutineScope、超时取消、动作提交前检查 cancellation；无法安全取消的动作返回 `unknown_side_effect`，随后强制 perceive 重建现场，禁止盲重试。
