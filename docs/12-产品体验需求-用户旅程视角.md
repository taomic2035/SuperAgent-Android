# 12 · 产品体验需求（用户旅程视角，2026-08-19 用户口述立项）

> 来源：用户以最终用户视角定义的五步产品体验。本文= 旅程逐步对照现状 + 缺口 + 架构落位 + 分期计划。
> 优先级口径：交互层此前散落在 P1（语音环/UI 未入 P0 FR 树）——**本文将其升格为主线**。

## 1. 用户旅程 × 现状对照（诚实盘点）

| 步 | 用户期望 | 现状 | 判定 |
|---|---|---|---|
| 1 | 打开应用 / 语音呼出 | MainActivity 存在但是**开发者装配页**（启服务/开无障碍/授权麦克风三按钮）；语音呼出=通知栏"说话"按钮（ADR-6 P0 长按兜底）；无唤醒词（BD-04.5 P1） | ◐ 退化可用 |
| 2 | 后台开启并常驻 | FGS+a11y 存在；但华为杀过进程（TTS native 崩）、**会拦 START_STICKY 重启**（已观测）、无自愈看门狗 | ◐ 可靠性不达标 |
| 3 | **Siri 式半透悬浮窗输入（打字+语音）** | **完全缺失**。现有输入=PC REPL（开发工具）；无悬浮窗、无 SAW 权限、无产品输入 UI；FR 树（docs/06）无此 FR | ❌ **最大缺口** |
| 4 | 精准理解、规划路径 | brain/GLM 已验证（G1/G2 里程碑）；ASR 真机 PASS | ✅ |
| 5 | 执行 | 操控/红线/回放全部落地（M1/M3） | ✅ |
| 6 | 反馈 | TTS vits 修复中；文字反馈只在 REPL；无产品级反馈呈现 | ◐ |
| 7 | **全程步骤/状态显示（不占焦点不挡视线）** | **完全缺失**。数据层已备（EventBus 5 类事件 + VoiceLoop 状态机 idle→listening→…→speaking），**无任何 UI 渲染** | ❌ 数据有、皮没有 |

## 2. 缺口根因

架构上我们把"身体"做成了 RPC 服务，交互层被合理地推迟（P0 验收用 PC REPL 代行输入/输出）。但产品承诺里**用户看到的就是交互层**——链路再绿，没有悬浮窗与步骤流，用户视角=不可用。此判断与 docs/01 市场定位一致（对标 Siri/小艺的随身 agent）。

## 3. 架构落位（复用既有件，不另起炉灶）

### 3.1 悬浮交互层（body 内，新 BD-10）
- `TYPE_APPLICATION_OVERLAY` 半透悬浮条（SAW 权限引导——**顺带解掉 BAL 限制**，审计遗留 #4b 一并收益）
- 形态：收起=侧边小胶囊（状态色点=VoiceLoop 状态）；展开=半透卡片（输入框 + 麦克风按钮 + 步骤流列表）
- 输入路径 A（打字）：`text_input` 事件入 EventBus → brain 语音环轮询消费（等价现有 voice trigger，携带文本免 ASR）
- 输入路径 B（语音）：悬浮窗麦克按钮 → `speech.asr`（已验证）→ 同上
- 步骤流渲染：**brain→body 事件回灌**——新增 brain RPC `brain.event`（body 提供，brain 上报"感知中/第 N 步 tap(…)/等待确认/完成+证据"），body EventBus 广播 → 悬浮窗订阅（同进程直连）
- 不占焦点：overlay 不抢 focus（FLAG_NOT_FOCUSABLE 常态，输入时临时切换）；步骤流半透滚动

### 3.2 常驻可靠性（新 BD-11）
- 看门狗：FGS 内定时自检（health/a11y 断连→自愈重启流程）；workscheduler 兜底拉活
- 崩溃死亡上报：uncaught handler → 通知用户"躯体已重启"（对齐 agentos SYS-004 显式死亡事件语义）

### 3.3 呼出（BD-04.5 维持 P1 + 快捷入口）
- P0：通知栏常驻 + 悬浮胶囊即入口；P1：KWS 唤醒词

## 4. 分期（并入 docs/10 主线）

- **UI-0（1-2 天量级）**：悬浮胶囊+展开卡片+打字输入+text_input 事件+brain 语音环消费+基础步骤流（brain.event 回灌 8 类状态）→ **用户旅程 1/3/4/5/6(文字)/7 打通**
- **UI-1**：悬浮窗语音按钮（复用 speech.asr）+ TTS 反馈（vits 验证后）+ 状态色点动效
- **UI-2（P1 窗）**：KWS 唤醒、看门狗全量、锁屏体验
- 验收：真机全程不碰 PC——悬浮窗输入"点一杯奶茶"→看步骤流执行→语音/文字回报
