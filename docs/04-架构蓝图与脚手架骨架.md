## 1. 综合设计：四项目各取什么

```
超级 AI 助手 = 大脑(pi) + 躯体(Kestrel) + 人设(Clowder) + 权威(MiraAgent)
```

| 来源 | 吸收的核心 | 不吸收的 |
|------|-----------|---------|
| **pi** | Agent loop / 工具调用与事件流 / steering / 会话状态 / 多 Provider LLM | TUI、coding 工具集、MCP、plan mode（Android 侧有自有守卫） |
| **Kestrel** | Action DSL、GestureBackend、感知路由、技能学习/回放/治理、证据闸门、支付红线、A11yRebinder、HITL、订单跟踪 | Kotlin 编排层（被 pi loop 替代）、云端单模型绑定（改 pi-ai 多 Provider） |
| **Clowder** | VoiceConfig 音色契约、per-agent 声线、流式 TTS 分句、播放队列/打断、身份常驻、技能 manifest、A2A（后期） | Redis/Node 平台（换 Termux/Java）、浏览器前端（换 Android UI） |
| **MiraAgent** | 五平面责任切分、Claim/Evidence/Fact 分离、幂等/fencing/预算租约、Unknown 一等状态、渐进信任、mock/real 同契约、验证链 | 全套 ROM 依赖（作为深度定制档演进）、文档治理流程 |

## 2. 目标架构（双进程 + 三档位）

### 2.1 进程拓扑

```
┌──────── Termux 进程（大脑 · Node/TypeScript）───────────────────────┐
│  pi-agent-core loop（prompt/tool/steering/事件流）                  │
│  pi-ai（GLM-4.6V 视觉主路 / DeepSeek·GLM 文本 / 多 Provider）       │
│  工具注册表：android.* 工具（经 IPC 调躯体）+ 技能路由工具           │
│  会话 SQLite（pi session backend）+ personas（Clowder 身份模型）    │
│  llama.cpp（端侧 Qwen3.5-2B int4 离线兜底，可选进程）               │
└─────────────┬───────────────────────────────────────────────────────┘
              │ localhost JSON-RPC(HTTP) + WebSocket 事件流（token 鉴权）
┌─────────────▼──────── Android 前台服务（躯体 · Java/Kotlin）────────┐
│  hardware/   音频路由·麦克风·传感器·振动·耳机插拔（HardwareProvider）│
│  speech/     sherpa-onnx JNI：ASR·TTS·声纹·VAD（懒加载/LRU）         │
│  control/    GestureBackend：dispatchGesture·语义点击·按键·手势     │
│  perception/ a11y·截图·OCR·SoM·脱敏·感知路由·页面签名                │
│  skill/      技能库 Room·学习·回放·Curator·usage 统计               │
│  hitl/       敏感确认·验证码回填·人工接管·支付红线                  │
│  ui/         悬浮球·通知·HITL 卡片（Compose）                       │
│  core/       IPC server·watchdog(Termux 探活重启)·审计日志          │
└──────────────────────────────────────────────────────────────────────┘
```

### 2.2 三档位

| 档位 | 交付形态 | 能力 |
|------|---------|------|
| **L1 免 root App** | APK 侧载（前台服务 + a11y + 悬浮窗） | 全部核心能力；按键注入限 Back/Home/Recents |
| **L2 Shizuku 增强** | 同一 APK + Shizuku 提权（用户授权） | 深度按键注入（音量/电源/组合键）、更深系统调用 |
| **L3 AOSP 深度定制** | ROM 集成（MiraAgent 路线） | InputManager 注入、系统级保活、AppOps/SELinux 边界、framework Broker |

### 2.3 五平面责任（MiraAgent 思想落地）

| 平面 | 归属 | 写权 |
|------|------|------|
| 输入 | Android 事件（语音/文字/通知/传感器/Intent） | 无 |
| 认知内核 | pi-agent-core（Termux） | **无 canonical 写权**，只产出 Claim/计划/工具调用 |
| 智能 | pi-ai 多 Provider + llama.cpp + 声纹识别 | 无 |
| 执行 | Java 躯体（技能回放=确定性执行；模型步=工具执行） | 经 HITL/证据闸门后提交 |
| 输出 | 音频路由/振动/通知/悬浮窗 | 无 |

**关键约束（借 MiraAgent ADR-001）**：R1 业务提交权威（目标/技能/记忆）与 R2 动作提交权威（副作用最终校验）**逻辑分立**——Termux 大脑即使幻觉/被攻破，也无法绕过 Java 侧证据闸门与支付红线直接动手机。

## 4. 脚手架规格逐项（对应需求清单）

### 4.1 硬件模块（听筒/扬声器/耳机外设/Mic/传感器/振动）

| 子项 | 规格 | 验收标准 |
|------|------|---------|
| 听筒 | `setCommunicationDevice`（API31+）切听筒声学路径 | 播报走听筒成功 |
| 扬声器 | `setSpeakerphoneOn` + AudioTrack 输出 | 免提播报成功 |
| 耳机外设 | `AudioDeviceCallback` 监听插拔 → 自动重路由 + 事件通知大脑 | 插耳机 TTS 自动切耳机；插拔事件入上下文 |
| Mic | AudioRecord 16k mono → ASR；48k 多声道 → 声纹 | 双采样率切换无异常 |
| 传感器 | 姿态（拿起/静置/翻转/行走）、光线（暗光调 UI）、接近（熄屏策略） | 传感器事件流供大脑决策 |
| 振动 | 波形：提醒/来电/节拍/自定义序列（`VibrationEffect.createWaveform`） | 三类波形可复现 |

### 4.2 语音业务（TTS/ASR/声纹/音色/语气/语调）

| 子项 | 规格 |
|------|------|
| ASR | SenseVoice int8 端侧；VAD 自动断点 + 按住说话双模式；15s 安全帽；语种自动 |
| TTS | Kokoro 中文主路；流式分句合成；播放队列（critical>high>normal>low）+ interrupt |
| 声纹 | 注册 N 个说话人；识别"主人/他人"；多角色语音命令分流 |
| 音色 | VoiceConfig 每角色独立（refAudio+refText+instruct+temperature）；缓存 hash 含全部参数（防串台） |
| 语气/语调 | instruct 指令驱动 + speed 微调；云端 Qwen3-TTS 增强可选 |
| 打断 | VAD onSpeechStart → 立即打断播报（hands-free 双向对话） |

### 4.3 操控（按键/触屏/手势）

| 子项 | 规格 |
|------|------|
| 触屏 | Tap/LongPress/Swipe（dispatchGesture，110ms+2px 微位移）；坐标 Norm 0..999 归一化 |
| 按键 | Back/Home/Recents（a11y 免费）；音量/电源/组合键（Shizuku 档）；InputManager（ROM 档） |
| 手势 | 双指缩放/旋转、组合手势（GestureFactory 扩展 DSL） |
| 语义点击 | TV/无触屏走 ACTION_CLICK/SCROLL/LONG_CLICK；WebView 子树退回手势像素点 |
| 可信度 | located 如实反馈 + 像素校验（SelectSpec 区域 diff，防"点了没选中"） |

### 4.4 屏幕识别

| 子项 | 规格 |
|------|------|
| a11y | 交互节点提取 + 后代文本兜底 + 选中标记 + 密码敏感标记 |
| 截图 | a11y takeScreenshot 优先（免 MediaProjection）；JPEG q78；OverlayGate 防自家 HUD；BlankGuard 白屏守门 |
| OCR | PaddleOCR-ONNX 端侧（中英），文本化 SoM（行桶 y/40 + 列桶 x/200 去重 + 阅读序 + 限量 40） |
| 视觉徽章 | 编号画上截图，云视觉看图读号（MarkBadgeRenderer） |
| 云视觉 | GLM-4.6V grounding（主路）；感知路由按可信度（a11y 0.9 / 视觉 0.6） |
| 签名 | UiSignature（a11y）+ aHash（视觉），感知/执行/技能三方同源 |
| 脱敏 | 敏感区域遮黑；不可遮 → 置空不上云（UploadRedactionPolicy 三态） |

### 4.5 复杂业务路径规划

| 子项 | 规格 |
|------|------|
| 双路径 | 技能命中 → 确定性回放（零模型）；未命中/UI 变 → 云 ReAct → 成功即学 |
| 技能 | SKILL.md 数据型（YAML frontmatter + steps）；TF-IDF 检索（≥0.30 离线命中）；Curator 治理（ACTIVE/STALE/ARCHIVED）；usage 精确归因 |
| 规划守卫 | MaxSteps/NoProgress/Stuck/Oscillation/Looping 五级逃逸 + 升级式自恢复（Back → Launch） |
| 证据闸门 | finish 必须附屏上**新颖**证据（存在性+新颖性）；技能回放成功 ≠ 目标完成（续跑 reactLoop 裁决） |
| 红线 | 支付永不自动（isPaymentCommit 只看**目标元素**文字）；sensitiveHandoff 记成功不惩罚 |
| 离线 | 技能命中确定性回放；新任务 llama.cpp 端侧逐步决策兜底 |
| 权威 | 深度档：attempt/epoch/fence 幂等、预算租约守恒、Unknown 禁盲重试、追加式历史 |

## 5. 核心机制规格

### 5.1 IPC 协议（Termux ↔ 躯体）

```
请求  : { "id": 1, "method": "control.tap", "params": { "x": 500, "y": 300 } }
回执  : { "id": 1, "ok": true, "located": true, "signature": "a1b2..." }
事件  : WS 推送 { "type": "progress" | "voice_chunk" | "hitl" | "sensor" | "state", ... }
```

- JSON-RPC over HTTP（命令/回执）+ WebSocket（事件流，复用 Clowder voice_stream 事件语义）；
- 鉴权：localhost + 启动 token；躯体拒绝外部连接；
- 错误契约：`denial is data`——typed 结果（AVAILABLE/STALE/DENIED/UNAVAILABLE），绝不裸 boolean；
- 幂等：工具调用带 idempotency key，躯体按 key 去重（MiraAgent 幂等思想）。

### 5.2 领域守卫挂点（pi beforeToolCall/afterToolCall）

| 守卫 | 挂点 | 逻辑 |
|------|------|------|
| paymentGuard | beforeToolCall | 目标元素文字命中支付词 → block + HITL；用户确认也不放行（红线） |
| sensitiveGuard | beforeToolCall | 敏感操作（短信/通讯录/相机/位置）→ 逐次确认 |
| finishGuard | afterToolCall | finish 证据：重新感知 → 存在性 + 新颖性核验 → 不符则驳回并续跑 |
| skillGuard | beforeToolCall(run_skill) | 技能按起始帧包名过滤 + 离线相关度阈值 |
| budgetGuard | afterToolCall | 步数/费用/时间租约，超限 → 转 HITL（Kestrel needHumanRetries 封顶） |

### 5.3 保活矩阵

| 层 | 机制 |
|----|------|
| 躯体 | 前台服务（microphone 类型）+ 免优化引导 + HITL 卡片保活跃 |
| 无障碍 | A11yRebinder（仅"设置仍启用却被解绑"时自愈重绑，用户主动关闭绝不强写） |
| Termux 大脑 | 躯体 watchdog：/health 探活，死亡 → RUN_COMMAND 重启 + 会话恢复（pi session backend） |
| 深度定制 | L3：系统白名单/foregroundServiceType 豁免 |

## 7. 结论

- **脚手架 = 双进程（Termux 大脑 + Java 躯体）+ 三档位（免root/Shizuku/AOSP）**，职责边界：大脑只认知、躯体只执行、权威分立（R1/R2）；
- **四项目融合方式**：pi 提供 loop 与工具模型（唯一复用）、Kestrel 提供操控/感知/技能全栈、Clowder 提供语音人设与音色契约、MiraAgent 提供系统级权威与验证链；
- **风险最低路径**：L1 免 root 快速闭环 → L3 AOSP 深度定制按独立里程碑演进，两档共享同一套 Action DSL / 端口 / 技能 / 守卫规格。
